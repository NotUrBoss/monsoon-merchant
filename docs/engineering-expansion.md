# Network Company engineering review

Implemented an independent pure engine in logistics.js with a browser and Node interface. Classic season state and storage are not coupled to this mode. Network Company offers fourteen hubs in five regions, twelve products, five explicit rail corridors, distinct sea/air/rail capacity and pricing, parallel dispatch slots, local warehouses, four manufacturing recipes and a single global 60-day clock.

All economic mutations validate the complete incoming state and preflight stock, cash, supported accounting bounds, storage reservations, factory limits and deadline constraints before committing. Quantities are positive safe integers. Incoming shipments and production output reserve destination space immediately. Invalid actions do not partly consume cash or cargo. Fixed transport fees, finite slots, a ten-batch production limit, finite daily market stock and bid/ask spreads bound same-day exploitation. Land freight is restricted to named corridors, with terminal transfers represented in cost and duration.

Save files use a separate strict version 1 schema. Validation covers all hubs/products, warehouse capacity, duplicate jobs, job timing/freight costs, recipe outputs, calendar, money, statistics, history limits and final valuation. Unknown top-level data and prototype keys are rejected. Deserialize has a 1 MB input limit. Client-local saves remain editable by their owner; there is no competitive server authority or network backend. Text from imported history and seed must still be escaped by the UI.

Facilities add ongoing upkeep; cash shortfalls accrue explicit debt, which future sale proceeds repay first. Day 60 settles the company at current market inventory prices plus 60% warehouse and upgrade resale and 50% factory/dispatch upgrade resale, minus debt. The initial company value is RM 542,000 (RM 500,000 cash plus the initial warehouse resale value). No operation may finish after day 60, so the final statement contains no unresolved shipments or production.

Validation: all 15 logistics tests passed. Coverage includes thirty complete 60-day companies with save/load on every day, ninety sea/air/rail deliveries, over 25,000 tonnes produced; active and finished save roundtrips; parallel capacity reservations; cash/debt accounting; every recipe; legal rail connections; all failure paths for finite quantities and supported accounting limits; malformed backups and prototype keys. The final integrated test suite passed all 50 tests; browser verification covered concurrent transport and manufacturing, sales, reload, valid and invalid restore, and the complete 60-day campaign.

Balance adjustments from creative review were implemented: machinery base value raised to RM 39,000 to avoid a structurally unprofitable recipe; factories capped at ten batches per job. Remaining deliberate simplifications: markets use reproducible seeded prices in three-day windows, rail timings include abstract terminal transfers, no customs, no player-built tracks, no storage spoilage, and no multiplayer authority. These are optional future features rather than unfinished actions in the current mode.

## Independent UI integration review

Independent review found and the implementation fixed two integration defects. Destination normalization now runs before every render and when the managed hub changes, keeping the selected destination and shipment quote aligned after start, continue and restore. Browser regression verification confirmed that restoring a Klang company from a previously selected Singapore hub produces a valid Singapore destination. A disposed-instance guard now prevents clipboard callbacks and render calls from repainting a closed Network Company screen; this fix was verified by source review, without claiming a successful clipboard transfer. The day-60 transition now announces the completed season and final company value and moves keyboard focus to the summary heading; both behaviors were confirmed in the browser.

No additional defect found in backup restoration atomicity, backup HTML escaping, quantity input selection restoration, or classic delegated event separation. Failed restore keeps the existing company; state mutations persist after successful preflight; classic listeners use distinct data-a controls and suspend classic rendering while the Network screen owns its mount.
